# 测试说明与手动验证清单

本文档覆盖两个必须功能：

- 自动识别当前浏览器，并打开对应原生书签管理页。
- 当前浏览器已有、但扩展管理页索引缺失的书签会被自动补齐。

## 验证前准备

1. 在 Chrome 或 Edge 中加载 `D:\Test` 作为未打包扩展。
2. 准备几个可识别的测试书签，例如：

```text
https://example.com/?bm-test=chrome-only
https://example.org/?bm-test=edge-only
https://developer.mozilla.org/?bm-test=common
```

3. 打开扩展 popup 或管理页，确认能看到当前浏览器名称、原生书签页地址、同步状态和书签列表。

## 手动验证清单

| 编号 | 场景 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| B-01 | Chrome 浏览器识别 | 在 Chrome 中点击“打开原生书签页” | 打开 `chrome://bookmarks/` |
| B-02 | Edge 浏览器识别 | 在 Edge 中点击“打开原生书签页” | 打开 `edge://favorites/` |
| B-03 | Chrome 缺失书签补齐 | 在 Chrome 原生书签中新增测试书签，清空扩展索引，再打开管理页或点击“重新同步” | 管理页重新出现该书签，`本次补齐` 大于 0 |
| B-04 | Edge 缺失书签补齐 | 在 Edge 原生收藏夹中新增测试书签，清空扩展索引，再打开管理页或点击“重新同步” | 管理页重新出现该收藏项，且不影响 Chrome profile |
| B-05 | 无缺失书签 | 浏览器书签和扩展索引一致时触发同步 | 不产生重复项 |
| B-06 | 重复 URL 不同目录 | 在两个不同文件夹下添加相同 URL 后同步 | 两个书签都保留，因为索引使用浏览器书签 id |
| B-07 | 空标题书签 | 新增标题为空或很短的书签后同步 | 同步不报错，管理页显示 URL 或原始标题 |
| B-08 | 深层文件夹 | 在多层文件夹中新增书签后同步 | 管理页能补齐书签并保留 `parentId` |
| B-09 | 改名或移动 | 修改原生书签标题、URL 或父级目录后同步 | 已有索引项更新，不新增重复项 |
| B-10 | 权限缺失 | 临时移除 `bookmarks` 或 `tabs` 权限后重载 | 页面显示可诊断错误，不静默成功 |

## 快速验证缺失补齐

在扩展管理页或 popup 的开发者工具控制台执行：

```js
chrome.storage.local.remove("betterBookmarkManager.index.v1");
```

然后执行任一操作：

- 重新打开 popup。
- 重新打开管理页。
- 在管理页点击“重新同步”。
- 在浏览器原生书签页新增、改名或移动一个测试书签。

期望结果：

- 管理页“管理页记录”重新增长。
- 管理页“本次补齐”显示本轮新增数量。
- popup 显示“已补齐 N 个缺失书签”或“管理页索引已是最新”。
- 刷新管理页后补齐结果仍然存在。

## 技术验收点

- 浏览器识别逻辑集中在 `src/browserDetection.js`。
- 书签补齐逻辑集中在 `src/bookmarkSync.js`。
- 同步使用 `chrome.bookmarks.getTree()` 读取真实书签树。
- 管理页索引使用浏览器书签 `id` 作为主键，避免相同 URL 在不同文件夹中被误合并。
- 文件夹节点不会被当作普通 URL 书签写入索引。
